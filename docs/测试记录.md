## v0.1.1 DeepSeek 配置与请求修正

用户反馈首版 HTTP 400。只读取随译自己的非敏感设置发现模型名保存为裸 `deepseek`；用户随后更改模型名，反馈翻译已正常。此反馈确认具体模型标识是本次配置问题。未读取、导出或替用户使用其会话密钥，也未将截图正文发送给模型。

修正版在 Core 和设置保存阶段拒绝这个裸模型名，提示使用具体标识；DeepSeek 官方精确主机的请求不发送文档未列出的 `store`，显式发送 `thinking.disabled` 与 `stream:false`。这属于协议适配完善，不把 store 或默认 thinking 断言为本次 400 原因。400/422 有限错误解析仅输出固定诊断，不回显原服务错误内容。

本轮完整 Core / App / 测试构建 **0 警告、0 错误**；自动断言 **61/61 通过**，实际 Shown WPF 检查 **17/17 通过**。新增断言覆盖 DeepSeek 参数、精确主机 / 端口、模型名发送前拒绝，以及带虚构密钥 / 正文的错误回显隔离；新增窗口检查证明裸模型名保存被拒绝且 Apply 未调用。

协议与错误测试为内存假响应，UI 为模拟固定样例；v0.1.1 的新参数分支仍需用户本地实际调用复验。本轮未关闭用户正在运行的首版。首版当前可继续使用；修正版作为可选更新交付。
